# Life-Sync — 第1段階の実装

Next.js / TypeScript / Tailwind CSS / Supabase REST API。Vercelへの公開を基本とする構成です。新規の専用Supabaseプロジェクトを推奨します。

## 接続する前に

現在は明示的な体験モードです。サンプルの「こむぎ」が表示されます。追加・編集・削除の操作はタブ内のみで、再読み込みでリセットされます。ユーザーデータをlocalStorageに保存しません。本番の保存完了とは表示しません。

## Supabase接続手順

1. Supabaseで既存プロジェクトを開く。ConnectまたはSettings → APIでURLと公開anonキー/publishableキーを取得。service_roleキーはフロントエンドに設定しない。
2. SQL Editorで `supabase/schema.sql` を確認して実行。既存のpets/entries/pet-mediaがある場合は、そのまま実行せずマイグレーションを調整する。
3. `.env.example` を `.env` にコピーし、2つの公開設定を入力。Vercelでも同じ環境変数を設定して再ビルドする（クライアントに埋め込まれる公開設定）。
4. AuthenticationでEmail認証とメール確認を有効化。公開URLをSite URLおよびRedirect URLsに設定。メールの実配送はプロバイダ設定を確認する。
5. 登録→確認メール→ログイン→ペット作成→健康/日記保存を確認。別のユーザーで他人のレコード/写真が見えないことを確認。

パスワード再設定メールの要求は実装済み。回復リンクからのパスワード変更画面は追加開発が必要です。セッションはタブ内保持のため、再読み込みすると再ログインします。トークン期限後には再ログインが必要です。長期利用向けセッション更新は追加開発が必要です。

## 画面構成

- ホーム：選択ペット、今日の記録、最近の思い出、健康ふりかえり
- ペット登録/編集：プロフィール、写真、複数ペット切り替え
- 健康管理：任意の項目で記録、編集・削除、期間別体重グラフ
- 思い出：写真/動画/PDF添付、日記編集・削除、タイムライン/カレンダー
- その子らしさ：プロフィールと飼い主の行動記録（AI推測ではない）
- AIアバター：写真の2D定型アニメーション試作。個体固有の動作解析は未実装
- メモリアル：命日、任意の切り替え、通常モードへの復帰、過去記録保持
- 設定：JSONエクスポート、ログアウト、ペット削除、未実装範囲

## データ設計

`auth.users` → `pets(user_id, data)` → `entries(user_id, pet_id, data)`。
複合外部キーで記録のユーザーとペット所有者を一致させ、RLSでアクセスを分離。アカウント削除時はDBのcascadeが基本記録を削除します。非公開StorageはユーザーUUIDのパスで所有者分離、署名URLで表示。署名URLは1時間有効です。

現時点ではペット/記録の削除はDBのみで、添付のStorageオブジェクトは残ります。ストレージの孤立ファイル清掃とアカウント削除の一括処理はリリース前に追加が必要です。JSONエクスポートには添付本体を含みません。写真動画を含む完全なバックアップ、アップロード失敗時の孤立ファイル回収も未実装です。

## 開発

Node 22.13以上、pnpm 11.25。`pnpm install`、`pnpm dev`。`pnpm exec tsc --noEmit`、`node --experimental-strip-types --test tests/core.test.ts`、`pnpm build`。
この環境にnpmがなかったため、同梱スターターをpnpmでインストールし、pnpm-lock.yamlを追加しました。
